# Этап 16 — интерактивное изображение и проверка качественного режима

Дата: 23.11.2026. Оборудование замеров: встроенная графика Intel (ANGLE, Direct3D11, `Intel(R) Graphics 0x0000A7AC`), Chrome через Playwright. Это не эталонный ПК D-08 (GTX 1660 SUPER) и не рабочий ПК с GTX 1050 Ti — выводы о скорости переносятся на них только качественно.

## 16.1–16.2. Интерактивный вид

- Освещение одно для всех комнат (`src/scene3d/SceneLighting.tsx`): полусфера, солнце с тенями (карта 2048, смещения против артефактов), привязанное к центру активной комнаты, окружение для отражений из процедурных световых панелей drei (без загрузки HDRI). Цветопередача — ACES Filmic, вывод sRGB (по умолчанию R3F), текстуры цвета в sRGB.
- Эталонная комната: `reference.png` (`node scripts/capture-stage16.mjs`) — кухня-гостиная схемы 2 комн.: ткань (диван, кресло, ковёр), дерево (журнальный стол, тумба), металл (торшер, люстра, мойка), керамика и пластик (холодильник), краска «шалфей». Сравнение с эталоном этапа 4 (`docs/stage-4/01-overview.png`): появились тени предметов на полу и отражения, картинка не хуже (D-07).

## 16.3. Браузерный path tracing (three-gpu-pathtracer)

Модуль `src/scene3d/qualitySnapshot.ts`: та же сцена и камера, цикл R3F на время снимка остановлен, `release()` возвращает редактор (проверено — после снятия редактор рисует как прежде).

Факты:

| Что | Результат |
|---|---|
| Совместимость версий | 0.0.24 ставится рядом с drei, но её шейдеры ссылаются на `cube_uv_reflection_fragment`, которого нет в three 0.187. 0.0.28 требует three-mesh-bvh ≥ 0.9.17, drei 10.7.9 закрепляет ^0.8.3 — поставлено через `overrides` (drei-компоненты с BVH в проекте не используются). |
| Окружение | PMREM-окружение сцены трассировщик с three 0.187 не принимает (та же причина) — на время снимка подставляется градиентное небо трассировщика. |
| Подготовка сцены | 1,1–1,7 с синхронно (BVH в основном потоке; асинхронный вариант требует отдельный worker). |
| Первая выборка | ≈ 230 с на этой машине — почти всё время уходит на компиляцию шейдера трассировки через ANGLE/D3D11 (предупреждения компилятора HLSL в журнале). 4, 8 и 64 выборки заняли 219–239 с. |
| Изображение | **Чёрное** (средняя яркость 0) при 8 и 64 выборках — снято внутри кадра трассировки (`toDataURL`), т. е. это не потеря буфера. Причина не установлена. |
| Альтернативный бэкенд | `--use-angle=gl`: WebGL2-контекст на этой машине не создаётся. |
| Статус библиотеки | `WebGLPathTracer` объявлен устаревшим; библиотека рекомендует `WebGPUPathTracer` (рендерер WebGPU three). |

Вывод: на доступном оборудовании «Качественный снимок» на WebGL-трассировщике не работает (чёрный кадр) и непригоден по времени (≈ 4 мин до первой выборки). Включение в релиз по D-09 требует решения пользователя (16.5): перейти на `WebGPUPathTracer` (отдельный рендерер WebGPU только для снимка; поддержка WebGPU в Chrome/Edge на Windows), продолжить отладку WebGL-варианта с проверкой на эталонном ПК, или явно отложить режим из первого релиза.

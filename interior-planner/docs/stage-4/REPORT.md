# Этап 4: отчёт технической сцены (задача 4.5)

Дата: 20.11.2026. Повтор: `npm run dev`, затем `node scripts/capture-stage4.mjs`.

## Оборудование и условия

- Рабочий ПК: Intel Core i5-10400, **Intel UHD 630** (Chrome выбрал встроенную видеокарту), Windows 10 Pro.
- Это **не** эталонный ПК D-08 (GTX 1660 SUPER); замеры промежуточные.
- Chrome (системный), окно 1920×1080, режим разработки Vite (без минификации).
- Сцена: одна техническая комната 420 × 350 см, три модели Poly Haven 1k, один направленный свет с тенями, полусферический свет.

## Замеры (`measurements.json`)

| Показатель | Значение | Порог D-08 |
|---|---|---|
| Частота кадров при вращении камеры | 60,2 кадра/с (ограничена частотой монитора) | ≥ 60 |
| Время кадра, 95-й процентиль | 16,8 мс | ≤ 20 мс |
| Готовность сцены (переход → пол в сцене) | 0,66 с | ≤ 3 с |
| Появление трёх моделей после расстановки | 0,65 с (первая загрузка, локальный сервер) | ≤ 2 с на модель |

## Кадры

- `01-overview.png` — общий вид сверху-сбоку, ближние стены скрыты.
- `02-corner.png` — вид изнутри от угла.
- `03-top.png` — вид сверху.

## Замеченные проблемы

1. Освещение плоское: нет карты окружения, тональная компрессия по умолчанию; стены выглядят одинаково серыми. Свет — этапы 16 и 21.
2. Полоса-артефакт на стене в `02-corner.png` (тень/стык стен) — проверить смещение тени (shadow bias) на этапе 16.
3. Стены — сплошные коробки без проёмов; окна и двери — этапы 9–10.
4. Подписи размеров на плане перекрываются мебелью — разметка выносится за контур на этапе 6.
5. Пол и стены без материалов (однотонные) — отделка, этапы 12 и 23.
6. Сборка: основной файл > 500 КБ — разбиение на этапе 18.
7. Скрытие ближних стен проверено только для прямоугольной комнаты с камерой снаружи.

## Что замеры не доказывают

- Соответствие порогам на эталонном ПК и для комнаты с полной расстановкой (15–25 предметов).
- Время загрузки моделей из сети (замер — с локального сервера, файлы малы).
- Качество финального изображения: это не фотореализм и не эталон «Качественного снимка».

## Решение

Архитектура (общая модель → функции domain → SVG и R3F; общий цикл переноса с проверкой через контракт изменения) работает сквозным образом. Менять её не требуется; продолжать по плану.
